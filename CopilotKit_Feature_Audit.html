useRenderTool Todo
Register a chat renderer for specific tool calls

V2 replacement for useCopilotAction's render prop. Registers a renderer that displays when the agent calls a specific tool. Receives {status: 'inProgress'|'executing'|'complete', parameters, result}. Supports wildcard ('*') fallback renderer. Intentionally does NOT remove the renderer on cleanup.

▶ Sample: wildcard renderer
import { useRenderTool } from "@copilotkit/react-core";

useRenderTool({
  toolName: "*",  // wildcard fallback for all tools
  render: ({ status, parameters, result }) => (
    <div className={status === "complete" ? "opacity-100" : "opacity-50"}>
      {status === "inProgress" && <Skeleton />}
      {status === "executing" && <Spinner />}
      {status === "complete" && <pre>{JSON.stringify(result, null, 2)}</pre>}
    </div>
  ),
});

L2 · In-chat Streaming Render Partial
Render React inside the chat bubble while the agent streams

The render prop of useCopilotAction receives { args, status } live as the model streams args. This lets you show a loading skeleton, then the final component, all inside the chat thread.

app/open/page.tsx (renderMarkdown — basic)
▶ Full streaming render pattern
useCopilotAction({
  name: "renderChart",
  render: ({ args, status }) => (
    <div>
      {status === "inProgress" && <Skeleton />}
      {status === "complete"   && <GenChart spec={args} />}
    </div>
  ),
  handler: async ({ kind, data }) => {
    // runs after agent finishes streaming
    setCharts(c => [{ kind, data }, ...c]);
    return "rendered";
  },
});
⚠️ renderMarkdown uses render:, but no status-aware progressive rendering

CopilotKitMiddleware Done
Official frontend-tool injection middleware

Wraps every model call to inject state.copilotkit.actions (frontend tools like renderUI) into the LLM's tool list, intercepts frontend tool calls so the ToolNode doesn't execute them, then restores them so AG-UI streams them to the browser. This is the fix for the original "model never calls renderUI" bug.

backend/agent.py
▶ Our usage
from copilotkit import CopilotKitMiddleware, CopilotKitState
from langchain.agents import create_agent

return create_agent(
    model=llm,
    tools=backend_tools,          # 14 SQLite/analytics tools
    middleware=[CopilotKitMiddleware()],
    state_schema=CopilotKitState,
    system_prompt=get_system_prompt(),
    checkpointer=MemorySaver(),
)
✅ Implemented. Event stream shows before_agent → model → after_model → after_agent lifecycle.

Core AG-UI Events OSS
Handled by the adapter — no custom code needed

The ag_ui_langgraph adapter emits all standard events automatically. Confirmed in our event stream.

  • STATE_SNAPSHOT — full state sync
  • MESSAGES_SNAPSHOT — message history sync
  • STEP_STARTED/FINISHED — graph node lifecycle

Human-in-the-Loop (HITL) Todo
Pause agent, ask user to confirm, resume

The agent can emit an interrupt and wait for the user to approve/reject an action (e.g. "Are you sure you want to delete these 50 records?"). CopilotKit surfaces an approval UI in chat. Requires LangGraph interrupt() + Command(resume=...).

▶ Sample (LangGraph tool)
from langgraph.types import interrupt, Command

@tool
async def delete_records(table: str, ids: list[int]):
    """Delete records after user confirmation."""
    approval = interrupt({
        "question": f"Delete {len(ids)} rows from {table}?",
        "options": ["yes", "no"],
    })
    if approval != "yes":
        return "Cancelled."
    # ... do delete
    return f"Deleted {len(ids)} rows."
❌ No confirmation dialogs — all actions fire immediately
